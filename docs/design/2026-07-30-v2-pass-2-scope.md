## 2. The refinement: conviction is earned, pressure is blind

> "agents should be encouraged to trade harder with achieving the goal in mind
> when they have found an edge in sessions. Never just blindly out of pressure
> of reaching a target." — owner, 2026-07-30

This is the load-bearing part of the scope, so it is treated first and proposed
as a formal amendment (**A-2**, part 3 below) rather than folded silently into a
workstream.

### 2.1 The asymmetry it corrects

The firm's current incentive gradient is one-sided, and deliberately so:

- **Over-sizing is structurally impossible.** `tier_from_score` sets a ceiling
  from evidence and every subsequent line in `risk/engine.py` can only *lower*
  it (drawdown cap, session-loss Exceptional demotion, five minimized
  capacities). `TierAdjustment.adjustment: int = Field(le=0)` makes raising
  unrepresentable (M-1). `profit_target: None` is a *type*, so the firm cannot
  represent a target and therefore cannot compute that it is behind one (§3.5).
- **Under-sizing is invisible.** Nothing measures it. A trader that holds E5
  evidence and claims E3 produces no error, no audit anomaly, no scored penalty.
  A trader that declares `direction: none` on a textbook setup looks identical
  to one that correctly stood aside. Caution is free at every level.

Free caution is not neutral. It is a systematic negative bias on expectancy that
no test currently detects, and it is exactly what the owner is objecting to. §6.6
already forbids the mirror-image failure — "do not reward an agent for taking
more trades" — but says nothing about an agent that consistently under-claims the
evidence it holds. That is the gap A-2 closes.

### 2.2 Why the distinction is machine-checkable, not a matter of tone

Conviction-driven sizing and pressure-driven sizing produce the *same action*.
They differ only in **inputs**. That makes the difference testable:

| Input class | Examples | Permitted effect on the tier ceiling |
|---|---|---|
| **Evidence** — a function of the market | evidence class, novelty class, registry feature values, analog sample statistics, regime fit, spread/slippage state | may raise the ceiling the gate *considers* |
| **Firm state** — a function of us | equity vs. any goal, days elapsed, cumulative return, session P&L, trades taken, time left in the window, prior losses | may only lower; may never raise |

The enforceable property follows directly:

> **Pressure invariance.** A thesis's evidence class, novelty class, and
> therefore its `max_edge_tier` must be a **pure function of the Market State
> Packet**. The same packet must yield a bit-identical classification regardless
> of firm state.

That is a property test, not a policy statement. It is the single most valuable
deliverable in this scope, and it is cheap once the packet exists (W1):

```
for firm_state in (flat, +300% and on day 44, -40% and restricted,
                   two losing trades today, one hour left in the window):
    assert classify(packet, firm_state).evidence_class == baseline.evidence_class
    assert classify(packet, firm_state).max_edge_tier  == baseline.max_edge_tier
```

If a future change lets desperation leak into classification, this test fails.
No amount of persuasive agent prose can defeat it, because the agent's prose is
not one of the inputs being compared.

### 2.3 The packet split this requires

§6A's packet list mixes both input classes — it includes "approved indicator
values" *and* "current positions, P&L, and risk capacity". Both are needed (a
trader must know it has no capacity), but they must not be interchangeable. Pass 2
therefore builds the packet as two typed halves under one checksum:

- **`MarketState`** — evidence-bearing. The only input the classifier may read.
  Enforced by signature: `classify(market: MarketState) -> Classification`. Firm
  state is not in scope of the function, so reading it is a type error, not a
  policy violation.
- **`FirmState`** — capacity-bearing. Reaches the risk engine, never the
  classifier. Carries no goal, no elapsed-day count, no cumulative return, and
  cannot carry a target because none can be represented.

Same M-1 move as before: make the wrong wiring fail to compile rather than fail
review.

### 2.4 Making conviction actually *reach*

Blocking pressure is the easy half; the owner asked for the other half too. Three
mechanisms, none of which touch the authorization path:

1. **The unreached-ceiling record.** Every decision already logs `tier` and
   `binding_constraint`. Pass 2 adds `thesis_ceiling` (from novelty × evidence)
   alongside them, so the audit trail distinguishes three cases: the *gate* bound
   (capacity, drawdown, margin), the *market* bound (evidence genuinely weak), or
   the *trader's own classification* bound while the deterministic features
   supported more. Only the third is a candidate miss — and today it is
   invisible.
2. **Under-classification scored as a calibration error (§6.6).** When the analog
   engine (W6) can later show a declined setup met the E4/E5 criteria on data the
   trader held at decision time, that is scored the same way over-claiming is.
   Symmetric, evidence-based, and applied post-session by the Learning Director —
   never in-session, where it would itself become pressure.
3. **`NOT_APPLICABLE` stays free; timidity does not.** §6.3 already requires an
   irrelevant specialist to return `NOT_APPLICABLE` rather than manufacture a
   signal, and §0 rule 6 makes "no trade" a preferred outcome. Neither is scored
   as a miss. What is scored is holding E5 evidence and *filing* E3.

### 2.5 What this refinement does not do — stated plainly

**It unlocks nothing today.** All three strategy manifests carry
`risk_permissions: {standard: false, strong: false, high: false, exceptional: false}`.
No thesis of any evidence class can currently produce any size at all. The route
to larger positions runs through §12.5 promotion and the §12.6 evidence
thresholds (30 signals / 50 trades / 100 candidates), and through nothing else.
Measured champion win rate is 48.4% with negative expectancy; the F-1 margin
overlay caps deployable risk near $1.80 on a 16-pip stop at $250 equity.

A-2 builds the mechanism by which *earned* conviction can express itself once the
evidence exists. It does not create evidence, advance a promotion, or raise a
permission. Any reading of "trade harder" that produces size before the evidence
does is the pressure response wearing conviction's clothes — and part 2.2's
invariance test exists precisely to catch it.

Nothing in A-2 adds an input to `risk/engine.py`'s authorization path. That
module's diff for Pass 2 is expected to be one added *output* field
(`thesis_ceiling`) and no added inputs.

## 3. Amendment A-2 — RATIFIED 2026-07-30

Following the A-1 precedent — implementer proposes, owner ratifies — the owner
ratified this amendment on 2026-07-30. It is now in force in the governing spec
at **v2.2.0**: the clause sits in §6.6, the pressure-invariance requirement in
§5.1, the precedence statement in §3.5, a unit test and an acceptance criterion
in §21, two definition-of-done lines in §25, and the changelist and ratification
record in §29. The text proposed and ratified was:

> **Conviction discipline.** The firm's evidence classification must be a pure
> function of the Market State Packet: identical packets yield identical
> classifications regardless of equity, elapsed time, session P&L, or progress
> toward any aspiration. Firm state may lower a candidate's tier and may never
> raise it.
>
> Within that constraint, the firm is expected to *claim the evidence it holds*.
> Systematically classifying below the evidence available is a calibration error
> scored symmetrically with classifying above it. Neither a correct `no trade`
> nor a correct `NOT_APPLICABLE` is a miss; filing E3 while holding E5 is.
>
> This clause creates no permission. It changes what is measured, not what is
> authorized. §3.5 (no profit target), §0 rule 6 (no forced trading), and §0
> rule 7 (no risk escalation after losses) are unaffected and continue to
> govern; where this clause and any of them appear to conflict, they win.

The last paragraph is deliberate. The 2026-07-30 decision-log entry that recorded
the return target as a goal ends: *"it exists so a future session reading the
earlier framing does not infer license to trade harder."* A-2 refines that entry
and must not be readable as reversing it. The conflict clause makes the
precedence explicit in the spec text itself rather than in this document.

## 4. Workstreams

Dependencies are noted; W1 gates most of the rest.

### W1 — Market State Packet runtime and checksum · §6A, §21

Deterministic construction from bars, features, spreads, calendar state, broker
health, and account state. Split into `MarketState` / `FirmState` per part 2.3, one
checksum over both, `packet_id` persisted to the audit chain.

*Acceptance:* identical inputs produce an identical checksum across processes;
both senior traders provably receive the same `packet_id`; a mutated packet is
detected; classification cannot read `FirmState` (type-level).
*Depends on:* nothing. **Do this first.**

### W2 — Senior Trader Alpha / Beta with context isolation · §6.2, §21

Two subagent runs in separate contexts, both fed one packet, each producing an
`AdaptiveThesis`. First-pass reports hashed and locked before either is
readable. Second-round responses must enumerate what changed after seeing the
opposing thesis.

*Acceptance:* the §21 criterion "Alpha cannot access Beta's first-pass report
before submitting its own, and vice versa" — enforced by construction (the
lock is a precondition of the read), tested by attempting the read early and
asserting failure.
*Depends on:* W1.

### W3 — Market Opportunity Arbiter · §6.1.D

Compares only after both locks. Must distinguish independent agreement from
duplicated evidence, must not average two weak theses into one strong one, may
declare no trade, and cannot transform E1/E2 into high-risk live exposure — the
last is already impossible by type (`EvidenceClass.max_edge_tier`), so the
Arbiter's constraint is tested against that existing guarantee rather than
reimplemented.

*Depends on:* W2.

### W4 — Specialist bench rewiring · §6.3

The three existing strategy specialists become consultable experts rather than
the firm's mandate. Deterministic relevance classifier; `NOT_APPLICABLE` as a
first-class, non-failing return; a specialist may support, reject, or qualify a
thesis but may not force its playbook.

*Acceptance:* §21 — "irrelevant specialists can return `NOT_APPLICABLE` without
causing workflow failure".
*Depends on:* W1. Parallel with W2/W3.

### W5 — Context and evidence agents · §6.4

Regime Analyst (K), Macro/Event Risk (L), Liquidity/Structure (M), Execution
Conditions (O). Each emits deterministic data, not chart prose. L fails closed on
missing or stale calendar data (§0 rule 10) — behavior already implemented for
the calendar; this wires the agent to it.

*Depends on:* W1.

### W6 — Historical Analog and Base-Rate engine · §6.4.N, §22 Phase 3

Search definition, analog count, similarity method, post-cost outcome
distribution, regime breakdown, threshold sensitivity, data limitations. Must not
cherry-pick after seeing the desired direction — enforced by requiring the query
definition to be committed and hashed *before* the direction is bound.

Note: this engine is a research code path and is therefore **publication-gated
under §12.7 / A-1**. No number it produces enters a validation report, promotion
record, or §12.6 evidence count until its code paths pass an independent,
refutation-default adversarial review.

*Depends on:* W1. Feeds A-2's under-classification scoring (part 2.4).

### W7 — Experiment and multiple-testing ledger · §12.4, §22 Phase 3

Persistent record of every hypothesis tested against every sample, so the
multiple-testing correction is computed rather than remembered. Seeds from the
existing state noted in the decision log: a breakout baseline, three spent
exit-variant tests, one first look each for sweep-reversal and continuation
against the GBP sample.

*Depends on:* nothing. Can run in parallel.

### W8 — Adaptive policy manifest · §11

`senior_trader_policy` as a versioned, immutable-in-production manifest:
approved feature/indicator/primitive registries, `allowed_novelty_classes_live`,
`required_evidence_class_by_risk_tier`, and the prohibited-behaviors list
(which already names `post_loss_risk_escalation` and `narrative_only_edge_claim`).
Changes to it are production changes under §12.5 promotion controls.

*Depends on:* nothing. Should land early — it is the artifact W2/W3 are bounded by.

### W9 — Agent definition refresh · §6, §7.1

The six files in `.claude/agents/` cite v1.1.3 and describe the v1 roster.
Rewrite against v2.2.0 and extend to the v2 roster. §6's own instruction —
"use the smallest number of high-quality agents that produces genuine
specialization; do not create agents merely to simulate a large firm" — argues
against shipping 21 stubs. **Owner decision 2026-07-30: nine agent files** — the
existing six, rewritten, plus Alpha, Beta, and Arbiter — with §6.4/§6.5 roles
consolidated into Chief Quant and Context Analyst as they already are. Recorded
as a deliberate deviation from the §6 letter, in service of the §6 instruction.

*Resolved — see part 7.*

### W10 — A-2 conviction discipline · §5.1, §6.6, §21, §25

The pressure-invariance property test (part 2.2), the `thesis_ceiling` audit
field (part 2.4), and the post-session under-classification scoring. A-2 is
ratified, so both halves are in scope: §21 now requires the invariance test as a
unit test and an acceptance criterion, and §25 requires the audit distinction.

*Depends on:* W1 for the test; W6 for the scoring.

### W11 — §21 acceptance tests requiring the agent layer

The four §21 criteria that Pass 1 could not reach: Alpha/Beta isolation,
`NOT_APPLICABLE` without workflow failure, and (already covered by type, to be
re-asserted end-to-end) N2/N3 cannot place live orders, N1 cannot receive
Exceptional.

*Depends on:* W2, W3, W4.

### W12 — Model routing policy · §7.4, §6.6

Frontier model for Alpha, Beta, Arbiter, governance, risk, quant review, and
promotion decisions; lower-cost models only for bounded extraction, formatting,
and log classification. §7.4's closing constraint is the test: routing must never
lower quality for a safety-critical decision to reduce cost.

*Depends on:* W9.

### Open findings against pending work

- **`analogs.py` direction guard is a denylist.** `_reject_direction_fields()`
  runs at import and catches nine direction-shaped field names, which is a good
